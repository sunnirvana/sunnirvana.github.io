Claude Code Cheatsheet

Claude Code

Anthropic 的终端编码 agent。当前钉在 v2.1.311（2026-10-26 发布）。原生安装会后台更新；交互会话默认从 auto 开始，claude -p 仍从 Manual 开始。大改动先 /plan。

v2.1.311 tag v2.1.311 更新于 2026-10-27

只想记一个命令

claude

在项目目录开一轮。第一次走浏览器登录。只要最终答案用 claude -p。先出方案不改代码：--permission-mode plan，或会话里 /plan。

复制按钮会复制可直接贴进终端或 Claude Code 会话的命令

最短记忆

免费的 claude.ai 计划不含 Claude Code。需要 Pro、Max、Team、Enterprise 或 Console 账号；也可以走 Bedrock、Google Cloud Agent Platform 或 Microsoft Foundry。

先装上

推荐原生安装。macOS / Linux / WSL 用下面这条。Windows PowerShell 用 irm https://claude.ai/install.ps1 | iex。装完新开一个终端，claude --version 能打出版本号才算在 PATH 上。

curl -fsSL https://claude.ai/install.sh | bash

登录

第一次跑 claude 会打开浏览器。已经设了 ANTHROPIC_API_KEY 并且你确认要用这把 key 时，会跳过登录。Console 按量计费加 --console；强制 SSO 加 --sso。

claude auth login

在项目里开一轮

进入仓库再启动。会话里 /init 会根据代码库起草 CLAUDE.md；文件已经存在时它提修改建议，不覆盖。想连技能和 hooks 一起走交互向导，先设 CLAUDE_CODE_NEW_INIT=1。

claude

坏了先诊断

终端里的 claude doctor 只读：安装、设置校验、Remote Control 资格，不改文件。会话里的 /doctor 会给出修复建议，你确认后才改。/status 看版本、模型、账号和加载了哪些设置来源。

claude doctor

按场景查

先找当前要做的事。命令表是 v2.1.311 文档的操作摘要，不是发布说明全文。

换一种安装方式

Homebrew：brew install --cask claude-code 跟 stable（大约晚一周，并跳过有严重回归的版本）；claude-code@latest 跟最新。WinGet：winget install Anthropic.ClaudeCode。原生 Windows 建议装 Git for Windows，否则 shell 走 PowerShell；沙箱只在 WSL 2 上支持，原生 Windows 和 WSL 1 都不支持。

brewwinget
brew install --cask claude-code

更新，或钉住频道

原生安装启动时和运行中会在后台检查，装好后下次启动才生效。claude update 立刻更新。频道写在设置里：autoUpdatesChannel 为 latest（默认）或 stable。Homebrew 的频道看 cask 名字，不看这个键。只停后台检查用 DISABLE_AUTOUPDATER=1，claude update 仍可用；连手动更新也要禁，用 DISABLE_UPDATES。

updatestable
claude update

看登录状态，或给 CI 发令牌

claude auth status 打 JSON，退出码 0 表示已登录、1 表示没有。--text 给人读。authMethod 会是 none、claude.ai、oauth_token、api_key、api_key_helper 或 third_party。CI 用订阅账号生成长效 OAuth：claude setup-token，令牌只打印、不落盘。

authci
claude auth status --text

接着上次，或点名恢复

claude -c 打开当前目录最近一次对话，包括已结束的后台会话。它默认跳过 claude -p、Agent SDK，以及第一条提示是 /loop 的会话；要连那些也续上，用 claude -p --continue。按名字或 ID：claude -r "auth-refactor"。想分叉出新会话 ID，加上 --fork-session。

-cresume
claude -c

脚本里只要最终答案

claude -p 跑完就退出，不进交互界面。从 v2.1.302 起，没指定权限模式的 -p 从 Manual 开始：需要批准的调用会被拒绝，除非你有 allow 规则、hook，或改成 --permission-mode auto。--output-format json 给程序读。--max-turns 和 --max-budget-usd 只在 print 模式生效；预算是客户端估算，子代理花费也计入，实际可能略超。

-pjson
claude -p "explain this function" --output-format json

先出方案，再改代码

Plan 模式读文件、跑只读探索命令，不改你的源码，直到你批准方案。启动时加 --permission-mode plan，或会话里 /plan，或 Shift+Tab 切过去。方案出来后可选：用 auto 模式执行、逐条批准编辑，或继续改方案。Ctrl+G 用外部编辑器改方案文本。再按一次 Shift+Tab 可以不批准就离开。

planShift+Tab
claude --permission-mode plan

选对权限模式

v2.1.283 起，交互终端和 VS Code 的内置起点是 auto（分类器在后台看 shell 和网络，而不是每步问你）。Shift+Tab 从 auto 先到 Manual（配置值 default），再是 acceptEdits，再到 plan。dontAsk 不在这个循环里，只给 -p / CI。 --dangerously-skip-permissions 等于 bypassPermissions，只适合容器或 VM。deny 规则在所有模式里仍然生效，包括 bypass。

automanual
claude --permission-mode default

少被问，但别放行危险命令

规则顺序是 deny，然后 ask，然后 allow。宽的 Bash(git push *) deny 盖得住更窄的 allow，allow 挖不出例外。/permissions 管理规则。Bash 上选 “Yes, and don't ask again” 会写进仓库根的 .claude/settings.local.json（v2.1.211 起，worktree 记在主检出根上）。文件编辑的批准只持续到这次会话结束，不写进文件。CLAUDE.md 说服不了权限系统。

denyallow
/permissions

让它记住项目约定

CLAUDE.md 是你写的上下文，不是强制配置。放构建命令、目录约定、可核对的规则；单文件尽量短于 200 行。项目用 ./CLAUDE.md 或 ./.claude/CLAUDE.md，个人跨项目用 ~/.claude/CLAUDE.md，只给自己的用 CLAUDE.local.md 并 gitignore。仓库里已有 AGENTS.md 时，Claude Code 可以把它当作项目说明来读。自动记忆由 Claude 自己写，每次会话加载前 200 行或 25KB。只对部分路径生效的说明放 .claude/rules/，用 paths frontmatter。

CLAUDE.mdrules
/init

设置放哪一份文件

从高到低：组织托管设置，然后本次 --settings，然后 .claude/settings.local.json，然后提交的 .claude/settings.json，最后 ~/.claude/settings.json。写在 .claude/settings.json 或 .claude/settings.local.json 里的 defaultMode: auto 和 bypassPermissions 不会当起点；用户文件里的 auto 可以。严格 JSON：注释和尾逗号会在下次启动报 Settings Error。多数键改完即重载；model 要改用 /model。换模型会使下一次请求重新读整段对话。

settingsprecedence
/status

接上 MCP

远程 HTTP 是推荐传输。--scope local（默认）只给你、只在当前项目；project 写到仓库根 .mcp.json；user 跨项目。密钥不要写进会提交的 .mcp.json。有 url 却没有 type 会被跳过。本地进程的参数放在 -- 后面。项目级服务器要在本机跑 claude 并批准；未信任目录里，提交进仓库的启用开关不会自己生效。会话里用 /mcp 做 OAuth。

mcp.mcp.json
claude mcp add --transport http notion https://mcp.notion.com/mcp

并行：worktree 与后台会话

claude -w feature-auth 在 .claude/worktrees/ 里开隔离检出。整段会话丢到后台：claude --bg "investigate the flaky test"，再用 claude agents 看、claude attach <id> 接回来、claude stop <id> 停。--bg 不能和 -p 一起用。后台主管无响应时，文档现在建议 claude daemon stop --any，这会结束它托管的后台会话；不要用已经停用的 daemon restart。

worktree--bg
claude -w feature-auth

上下文满了，或想旁问一句

/context 看窗口被什么占满。/compact 总结后继续同一段对话；/clear（别名 /new、/reset）开新对话，项目记忆还在。/btw 旁问一句，不写进对话历史。/rewind 把对话和/或代码退回检查点。/usage 看用量和限额。v2.1.311：标准上下文会话在请求超过 200K token 时会压缩后继续，不再停在 “Usage credits required for 1M context”。

compact/btw
/compact

怀疑是配置把它弄坏了

claude --safe-mode 不加载 CLAUDE.md、skills、插件、hooks、MCP、自定义命令和自动记忆，但登录、模型、内置工具和权限还在，用来判断是不是某项自定义触发了异常。脚本要更快、少做自动发现用 --bare：它会设 CLAUDE_CODE_SIMPLE，工具只留 Bash、读文件和改文件。两者不是一回事。/doctor prompt-audit 检查说明文件是否过时或互相打架，你点头之前不改文件。

safe-modebare
claude --safe-mode

换模型或推理档

别名有 sonnet、opus、haiku、fable，也可以写完整 ID，例如文档里的 claude-sonnet-5。/model 会把选择存成之后新会话的默认；在选择器里按 s 只改当前会话。--effort 可选 low、medium、high、xhigh、max、ultracode，不写入设置。v2.1.311：交互终端里的 ultrathink 会把这一轮提到 xhigh（Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.1，走 Anthropic API）；引号里或路径里的这个词不会触发。

modeleffort
claude --model sonnet --effort high

钉在 v2.1.311 时值得记住的修复

这一版修了几件日常会踩到的事：CLAUDE.md 里超长列表项导致启动和读写后长时间卡住；压缩之后仍读到更早改过的 MEMORY.md / CLAUDE.md 旧内容；子代理用不上启动之后才连上的 MCP 工具；在仓库子目录里 claude mcp add 把服务器记到当前文件夹而不是 ~/.claude.json 里的项目条目。说明文件仍建议单份 CLAUDE.md 控制在大约 200 行内。发布说明的其余修复以 changelog 为准。

常用流程

把几条命令串起来。具体工具名以你仓库的脚本为准。

第一次进一个仓库

先信任工作区，再起草说明、看记忆、收紧权限。提交的项目设置要等你信任这个目录才完全生效。

cd repo && claude→/init→/memory→/permissions

大改动先出方案

计划批准之后才会改文件。做完用 /diff 看工作区，/code-review 查正确性（/review 是它的别名）。

--permission-mode plan→批准方案→/diff

管道或 CI 里跑

精确允许名单用 dontAsk。想让分类器决定、又不用事先列命令，改成 --permission-mode auto。

claude -p→--permission-mode dontAsk→--allowedTools

换一台设备接着做

claude --teleport 把云端会话拉回本机终端，需要 claude.ai 订阅。本机这一轮想在手机或网页上接着控，用 claude --remote-control。macOS 和 x64 Windows、且是订阅登录时，claude --desktop 会把当前目录交给桌面应用后退出。

claude --teleport→或 --remote-control→或 --desktop

CLI 索引

在系统终端运行。权威来源是官方 CLI reference；claude --help 不会列出每一个 flag。

命令 什么时候用 备注
claude 在当前目录开交互会话。 claude "explain this project" 带上第一条提示。
claude -p "query" 非交互，跑完退出。 可接管道。--output-format text|json|stream-json。
claude -c 继续当前目录最近的对话。 默认不含 -p / SDK / 以 /loop 开头的会话。
claude -r "name" 按 ID 或名字恢复；不带参数则打开选择器。 仍在跑的后台会话会 attach 到这个终端。
claude update 立刻更新到当前频道的最新版。 claude install stable，或 claude install 加版本号。全新安装给安装脚本传 stable 或版本号，例如 bash -s stable。
claude auth login 登录、登出、看状态。 logout；status 加 --text。CI 用 claude setup-token。
claude doctor 不启动会话的只读诊断。 要它提议并应用修复，在会话里跑 /doctor。
claude --permission-mode plan 指定这一次的起点模式。 default（别名 manual）、acceptEdits、auto、dontAsk、bypassPermissions。
claude --model sonnet 这一次用哪个模型和推理档。 别名或完整 ID。档位用 --effort high，不持久化。
claude --add-dir ../lib 额外授予读写目录。 默认不加载那里的 .claude/ 与 CLAUDE.md。要加载记忆，设 CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1。
claude -w name 在隔离 git worktree 里启动。 路径在 .claude/worktrees/<name>。可加 --tmux。
claude --bg "task" 后台跑，马上把终端还你。 随后 claude agents、attach、logs、stop。不能和 -p 并用。
claude mcp add … 配置 MCP 服务器。 list / get 看状态。login <name> 走 OAuth，SSH 加 --no-browser。
claude plugin 安装和管理插件。别名 claude plugins。 例：claude plugin install code-review@claude-plugins-official。会话里用 /plugin。
claude --safe-mode 关掉自定义项来排障。 脚本瘦启动用 --bare，工具集更窄。
claude --settings ./settings.json 这一次盖过同名设置键。 免询问用 --allowedTools；从上下文拿掉工具用 --disallowedTools。
claude import codex --dry-run 从 Codex、Gemini CLI 或 Cursor 带入说明、MCP、命令和 skills。 --yes 跳过选择器。Bedrock / Vertex / Foundry 不可用。Cursor 需要 v2.1.265+。
claude --desktop 把目录交给桌面应用，或接云端 / 远程控制。 --teleport、--remote-control。桌面交接需要订阅，且限于 macOS 与 x64 Windows（v2.1.285+）。
claude --version 打印已安装版本。 本页钉的上游发布是 v2.1.311。

Slash 与模式

只在消息开头生效。输入 / 看你这个账号实际有的命令；组织和套餐会藏掉一部分。/help 列出当前会话能用的。

命令 做什么 备注
/init 起草项目 CLAUDE.md。 已有文件时给改进建议。CLAUDE_CODE_NEW_INIT=1 会多问 skills 和 hooks。
/plan [描述] 进入 plan 模式，可选地带上任务。 也可 Shift+Tab。批准前不改源码。
/permissions 管理 allow / ask / deny，以及工作目录。 别名 /allowed-tools。Claude 正在回复时打开，下一次工具调用就生效。
/config 主题、模型、输出风格等少数个人项。 别名 /settings。/config model=sonnet 可不打开菜单。/status 是同一对话框的 Status 页。
/model [模型] 换模型，并存成新会话默认。 选择器里按 s 只改这一次。/effort 调推理档；max 只对当前会话。
/memory 编辑 CLAUDE.md，开关自动记忆。 /context 看占用。/compact 总结。/clear 开新对话。
/rewind 把对话和/或代码退回检查点。 别名 /undo、/checkpoint。/diff 看改动。/code-review 查正确性。

/doctor 检查安装、设置、扩展和 CLAUDE.md，确认后才改。 别名 /checkup。/doctor prompt-audit 审说明文件（v2.1.283+）。

/login 会话内登录或登出。 /logout。/exit 离开；接在后台会话上时只是 detach。编辑模式在 /config，/vim 已在 v2.1.92 移除。部分终端的换行键位用 /terminal-setup。

这些路径各管什么

说明、权限和密钥不要放进同一个文件。Windows 上 ~/.claude 是 %USERPROFILE%\.claude；设了 CLAUDE_CONFIG_DIR 就改到那里。

路径 装什么 谁写
~/.claude/settings.json 你在这台机器上所有项目的偏好：主题、默认模型、个人权限。 你，或 /config。优先级最低的一份自有设置。
.claude/settings.json 团队共享的权限、hooks、插件、环境变量。 提交进 git。要等每个人信任该目录。

使用习惯

先 /init 把会重复解释的事实写进 CLAUDE.md，再开业务任务。大改动用 plan，小改动留在 auto 或 Manual。权限靠规则和模式，不靠提示词。密钥留在 local / user scope，不要进 .mcp.json。配置抽风先 claude --safe-mode，再 claude doctor。原生安装不用天天手动升；Homebrew、WinGet、apt、dnf、apk 要自己升，或给 Homebrew / WinGet 设 CLAUDE_CODE_PACKAGE_MANAGER_AUTO_UPDATE=1。HTML 块注释在注入上下文前会被剥掉，给人看的备注可以写在那里；代码块里的注释会保留。
