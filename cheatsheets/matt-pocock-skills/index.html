最短记忆

项目只跑一次

Code review 一个分支或 PR

从指定 commit、branch、tag 或 merge-base 开始，对 diff 做 standards 和 spec 两条线审查。

代码开始变乱

扫描代码库，找最值得做的架构改进点，再选择一个深入讨论。

把讨论变 spec

不继续采访，直接把当前对话和项目理解整理成 spec，并发布到项目配置的 issue tracker。

让后台 agent 做研究

边测试边报问题

交互式 QA 会话。你口述遇到的问题，它负责追问、补上下文并创建 durable issues。

先规划重构

解决 merge/rebase 冲突

把上下文交给下一轮

把当前对话压缩成 handoff 文档，适合换线程或让另一个 agent 接着做。

交接总结

常用流程

把多个 skill 串起来用，适合真实项目。

新功能从想法到代码

先对齐，再文档化，再拆 tickets，再实现，最后 review。

$grill-with-docs→$to-spec→$to-tickets→$implement→$code-review

修一个难复现 bug

先诊断，确认根因后用回归测试锁住行为。

$diagnosing-bugs→$tdd

实现后做 code review

先把实现跑通，再从固定点审查 diff 是否符合标准和规格。

$implement→$code-review since main

做一轮架构整理

先找机会点，再设计边界，最后用测试保护改动。

$improve-codebase-architecture→$codebase-design→$tdd

不知道从哪开始

把目标说清楚，让路由 skill 选流程。

$ask-matt→按它建议继续

Skill 什么时候用 典型提示
$setup-matt-pocock-skills 每个项目第一次使用这套工程 skills 前。 配置 issue tracker、triage labels、domain docs。
$ask-matt 不确定该用哪个 skill 或流程。 我想做……应该怎么走？
$batch-grill-me 按 design tree 的 frontier 分轮批量追问，一轮问完当前可问的问题。 请按 frontier 一轮一轮批量提问。
$wayfinder 规划一个超过单轮上下文的大项目、greenfield 项目或巨大功能。 把这个目标做成 wayfinder map。
$grill-with-docs 新功能、重要变更、需求不清楚。 我想做……先帮我把问题问清楚。
$grilling 底层追问循环，通常由 $grill-me 或 $grill-with-docs 调用。 请逐个问题追问这个计划。
$grill-me 非代码计划或设计也需要被追问。 我有个计划……请拷问我。
$tdd 写功能或修 bug，希望测试先行。 请用测试驱动实现……
$diagnosing-bugs 问题复杂、偶发、报错、慢、难定位。 这个问题是……请按诊断流程定位。
$improve-codebase-architecture 想主动发现代码库架构问题。 扫描这个项目，找出最值得改进的点。
$codebase-design 设计模块接口、边界、可测试性。 帮我设计这个模块的接口和边界。
$design-an-interface 想比较多个模块/API/interface 设计方案。 帮我为这个模块设计几个不同接口方案。
$domain-modeling 需要沉淀项目术语、领域模型、ADR。 帮我梳理这个领域概念并更新文档。
$ubiquitous-language 从当前对话提取 DDD 风格术语表。 把我们讨论的领域术语整理成 glossary。
$prototype 想用一次性原型验证设计想法。 我想验证这个交互或状态模型……
$to-spec 把已有讨论整理成 spec。v1.1.0 中替代原来的 $to-prd。 把上面的讨论整理成 spec。
$to-tickets 把 plan、spec 或 conversation 拆成 tracer-bullet tickets 和 blocking edges。 把这个 spec 拆成可实现的 tickets。
$to-questionnaire 把用户无法独自回答的问题转成给某个人填写的 discovery questionnaire。 为这个问题生成一份 questionnaire。
$triage 处理 issue 队列、分类和补充上下文。 帮我 triage 当前 issues。
$implement 已经有 PRD 或 issue，要直接实现。 请实现这个 issue。
$code-review 审查一个 branch、PR、WIP 或从某个固定点之后的改动。v1.1.0 中替代原来的 $review。 请 review 从 main 到当前 HEAD 的改动。
$research 让后台 agent 基于 primary sources 调查问题，并写成带引用的 Markdown。 请基于 primary sources 调查这个问题。
$qa 用户边测边口述问题，agent 帮忙追问并创建 issues。 开始 QA session，我会逐条报告问题。
$request-refactor-plan 先把重构计划拆成很小、可安全提交的步骤。 我想规划这次重构……
$resolving-merge-conflicts 当前处于 merge 或 rebase 冲突。 请解决当前冲突并解释取舍。
$git-guardrails-claude-code 为 Claude Code 设置 hooks，阻止危险 git 命令。 帮我设置 Claude Code 的 git guardrails。
$migrate-to-shoehorn 把测试里的 TypeScript as 断言迁移到 @total-typescript/shoehorn。 把这些测试迁移到 shoehorn。
$scaffold-exercises 创建课程练习目录、题目、答案和讲解结构。 帮我 scaffold 这一节 exercises。
$setup-pre-commit 配置 Husky pre-commit、lint-staged、Prettier、typecheck 和 tests。 帮这个项目设置 pre-commit hooks。
$setup-ts-deep-modules 为 TypeScript 项目设置 deep modules 相关约定和脚手架。 帮这个 TypeScript 项目设置 deep modules 约定。
$wizard 把第三方设置、一次性迁移等手工流程做成交互式 bash wizard。 帮我生成一个配置 X 的 wizard。
$loop-me 梳理可重复、可委托的工作流规格。 帮我把这个反复做的流程梳理成 workflow spec。
$handoff 需要把当前上下文交给下一轮或另一个 agent。 下一轮要继续……请写 handoff。
$claude-handoff 面向 Claude Code 的 handoff 变体，用于交接上下文。 帮我写一个 Claude handoff。
$teach 让 agent 在当前 workspace 里持续教你一个概念或技能。 教我……
$writing-great-skills 写或改 agent skills 时参考的原则和词汇。 帮我改进这个 skill。
$edit-article 编辑、重组、润色文章草稿。 帮我编辑这篇文章。
$writing-fragments 写作探索阶段，先收集原始片段，不急着定结构。 帮我围绕这个主题挖写作 fragments。
$writing-shape 把已有素材塑造成一篇文章，逐段成稿。 把这些素材 shape 成文章。
$writing-beats 把素材组织成文章节奏和叙事 beats。 帮我把这些素材组织成 writing beats。
$obsidian-vault 管理 Obsidian vault 里的 notes、wikilinks 和索引。 帮我在 Obsidian 里整理这些 notes。
使用习惯

在真实项目根目录中启动 Codex，然后先跑 $setup-matt-pocock-skills。以后不确定时先用 $ask-matt。如果当前任务已经非常明确，直接用 $tdd、$diagnosing-bugs 或 $grill-with-docs。
