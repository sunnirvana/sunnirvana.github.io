Matt Pocock Skills

按项目工作场景查命令。先初始化一次，再按“想清楚、拆 spec/tickets、写代码、调问题、改结构、做 review、收工复盘”选 skill。

所有复制按钮都会复制可直接贴进 Codex 的提示词

最短记忆

不用记全套。主线仍是 grill → spec → tickets → implement；grilling 按 frontier 分轮提问。会话结束后可用 in-progress 的 $retro 复盘 agent 环境（仍是 stub）。

项目只跑一次

配置 issue tracker、triage labels、领域文档位置。之后其他 engineering skills 会读这些约定。

$setup-matt-pocock-skills

先把需求问清楚

新功能、重要改动、方案还模糊时用。会一边追问，一边沉淀术语、ADR 和上下文。

$grill-with-docs 我想做……

拆成 tickets

把方案、spec 或讨论结果拆成 tracer-bullet tickets，并声明 blocking edges。

$to-tickets 把上面的方案拆成 tickets

用测试驱动实现

开始写代码或修 bug 时用。强调一个行为一个测试，红绿重构，避免一次性写一大坨。

$tdd 实现第一个任务

按场景查

遇到 bug 或性能问题

Code review 一个分支或 PR

从指定 commit、branch、tag 或 merge-base 开始，对 diff 做 standards 和 spec 两条线审查。

code-reviewPRdiff
$code-review since main

代码开始变乱

扫描正在改的区域，找 deepening 机会。先看你指定的方向，否则看最近约 20 条 commit，不扫没人动的角落。

架构复杂度模块边界
$improve-codebase-architecture

把讨论变 spec

不继续采访，直接把当前对话和项目理解整理成 spec，并发布到项目配置的 issue tracker。

给刚结束的会话做复盘

in-progress stub。对照本轮 session（默认当前会话）找环境改进：导航指针、自动检查、coding standards、臃肿 AGENTS.md、tool 经济性、无效 steering，以及 Information access（日志 tee、只读第三方服务等）。按严重程度给出候选；实现与 review 分工不同，标准应压在 reviewer 侧。

retroin-progressstub

常用流程

把多个 skill 串起来用，适合真实项目。

新功能从想法到代码

先对齐，再文档化，再拆 tickets，再实现，最后 review。

$grill-with-docs→$to-spec→$to-tickets→$implement

修一个难复现 bug

先诊断，确认根因后用回归测试锁住行为。命令和输出先脱敏。

$diagnosing-bugs→$tdd

规划超出单轮的大工作

wayfinder 只做决策地图。地图清完后并回主流程，不要从地图直跳实现。

$wayfinder→$to-spec→$to-tickets→$implement

做一轮架构整理

先找正在改的路径上的 deepening 机会，再设计边界，最后用测试保护改动。

$improve-codebase-architecture→$codebase-design→$tdd

不知道从哪开始

把目标说清楚，让路由 skill 选流程。看不懂回复时立刻 $wait-what。

$ask-matt→按它建议继续

收工后复盘 agent 环境

先写/改 agent 文档原则，再对刚结束的会话做 retrospective。upstream 标为 stub，适合试反馈，不要当稳定流程。

$writing-for-agents→$retro

完整索引

基于 upstream v1.2.3 / main@3cca18b 整理的 37 个 skills（engineering 18 + productivity 7 + in-progress 8 + misc 4）。Claude Code 插件仍只带 25 个 promoted skills；in-progress 与 misc 需单独安装。本地 scripts/link-skills.sh 会链 promoted 与 in-progress，但不再把 misc/ 链进日常 skill 目录。日常优先用上面的主流程。

Skill 什么时候用 典型提示
$setup-matt-pocock-skills 每个项目第一次使用这套工程 skills 前。User-invoked。 配置 issue tracker、triage labels、domain docs。
$ask-matt 不确定该用哪个 skill 或流程。User-invoked 路由器。 我想做……应该怎么走？
$wait-what 上一句没落地。让它带上下文、用简化英语和项目术语重说。User-invoked。 上一句没听懂，请重说。
$wayfinder 规划超过单轮上下文的大工作。产出 decision tickets，清完后走 $to-spec。 把这个目标做成 wayfinder map。
$grill-with-docs 新功能、重要变更、需求不清楚。会边问边沉淀术语和 ADR。 我想做……先帮我把问题问清楚。
$grilling 底层追问循环。按 frontier 分轮提问；事实交给环境，决策留给人。 请按 frontier 分轮追问。
$grill-me 非代码计划或设计也需要被追问。不在工作目录时用它，而不是 $grill-with-docs。 我有个计划……请拷问我。
$tdd 写功能或修 bug。红绿循环，只在预先约定的 seam 上测。 请用测试驱动实现……
$diagnosing-bugs 问题复杂、偶发、报错、慢、难定位。展示命令和输出前先脱敏。 这个问题是……请按诊断流程定位。
$improve-codebase-architecture 扫描正在改的区域，找 deepening 机会，再选一个深入讨论。 扫描这个项目，找出最值得改进的点。
$codebase-design 设计模块接口、边界、可测试性。含 design-it-twice。 帮我设计这个模块的接口和边界。
$domain-modeling 需要沉淀项目术语、领域模型、ADR。吸收了原 $ubiquitous-language。 帮我梳理这个领域概念并更新文档。
$prototype 用单个可分享 HTML 验证设计问题，并作为 primary source 留在 throwaway 分支。 我想验证这个交互或状态模型……
$to-spec 把已有讨论整理成 spec，并发布到配置好的 issue tracker。 把上面的讨论整理成 spec。
$to-tickets 把 plan、spec 或 conversation 拆成 tracer-bullet tickets 和 blocking edges。 把这个 spec 拆成可实现的 tickets。
$to-questionnaire 把你无法独自回答的问题转成给某个人填写的 questionnaire。追问的是“寄给谁、要什么”，不是主题本身。 为这个问题生成一份 questionnaire。
$triage 处理 issue 队列、分类和补充上下文。原 $qa 的职责并到这里和 $to-tickets。 帮我 triage 当前 issues。
$implement 已经有 spec 或 tickets。在约定 seam 上跑 $tdd，完成后 $code-review 再提交。 请实现这个 spec 或 ticket。
$implement-spec in-progress。用子 agent + worktree 按 ticket graph 并发实现整份 spec，收口成一个 PR。 请按 spec 和 tickets 实现并开 PR。
$code-review 从固定点审查 diff：Standards 与 Spec 两条线并行。Standards 含 Fowler smell baseline。 请 review 从 main 到当前 HEAD 的改动。
$research 让后台 agent 基于 primary sources 调查问题，并写成带引用的 Markdown。 请基于 primary sources 调查这个问题。
$resolving-merge-conflicts 当前处于 merge 或 rebase 冲突。按双方原始意图解决，不 --abort。 请解决当前冲突并解释取舍。
$wizard 把只有人类能完成的步骤做成交互式 bash wizard。Model-invoked。 帮我生成一个配置 X 的 wizard。
$git-guardrails-claude-code misc（link-skills 不再自动链接）。为 Claude Code 设置 hooks，阻止危险 git 命令。 帮我设置 Claude Code 的 git guardrails。
$migrate-to-shoehorn misc（需单独安装）。把测试里的 TypeScript as 断言迁移到 @total-typescript/shoehorn。 把这些测试迁移到 shoehorn。
$scaffold-exercises misc（需单独安装）。创建课程练习目录、题目、答案和讲解结构。 帮我 scaffold 这一节 exercises。
$setup-pre-commit misc（需单独安装）。配置 Husky pre-commit、lint-staged、Prettier、typecheck 和 tests。 帮这个项目设置 pre-commit hooks。
$setup-ts-deep-modules in-progress。为 TypeScript 项目设置 deep modules 相关约定和脚手架。 帮这个 TypeScript 项目设置 deep modules 约定。
$loop-me in-progress。梳理可重复、可委托的工作流规格。 帮我把这个反复做的流程梳理成 workflow spec。
$retro in-progress stub。对刚结束的编码会话做 retrospective，按严重程度建议改进 agent 环境（导航、checks、standards、AGENTS.md、tool 经济性、no-ops、Information access）。配有 agents/openai.yaml，显式调用。 请复盘刚才这轮会话，列出环境改进候选。
$handoff 上下文需要搬走时用：新 harness、新目录、同事、或中途分叉。同一会话内优先 /compact。 下一轮要继续……请写 handoff。
$claude-handoff in-progress。面向 Claude Code 的 handoff 变体。 帮我写一个 Claude handoff。
$teach 让 agent 在当前 workspace 里持续教你一个概念或技能。 教我……
$writing-for-agents 写给 agent 看的文档：skills、AGENTS.md/CLAUDE.md。v1.2.0 由 $writing-great-skills 改名。 帮我改进这个 skill 或 agent 文档。
$writing-fragments in-progress。写作探索阶段，先收集原始片段。 帮我围绕这个主题挖写作 fragments。
$writing-shape in-progress。把已有素材塑造成一篇文章，逐段成稿。 把这些素材 shape 成文章。
$writing-beats in-progress。把素材组织成文章节奏和叙事 beats。 帮我把这些素材组织成 writing beats。
使用习惯

在真实项目根目录中启动 Codex 或 Claude Code，然后先跑 $setup-matt-pocock-skills。不确定时用 $ask-matt。看不懂上一句用 $wait-what。同一 harness、同一目录、到了阶段边界时，优先继续或 /compact，$handoff 只在上下文需要搬走时用。一轮编码收工后，可用 $retro 复盘 steering、checks、tooling 与信息获取；它是 in-progress stub，并配有 Codex 用的 agents/openai.yaml（显式调用，不隐式触发）。若你用仓库里的 link-skills.sh 做本地 symlink，现在只会链 promoted + in-progress，misc/ 要单独安装。
