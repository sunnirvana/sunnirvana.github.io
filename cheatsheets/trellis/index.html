Trellis Cheatsheet

Trellis

Mindfold 的 AI 编码工程化框架。把 Spec、任务、记忆沉淀进仓库；按场景查命令，复制后可贴进终端或会话。

v0.6.16 npm @mindfoldhq/trellis 更新于 2026-09-02

只想记一个命令

/trellis:continue

自然语言推进工作流；收尾用 /trellis:finish-work。

复制按钮会复制可直接贴进终端或 Agent 会话的命令

最短记忆

Node.js ≥ 18，Python ≥ 3.9。先装 CLI，再在仓库里 init。

先装 CLI

全局安装最新版。旧 CLI 也可用 trellis upgrade。

npm install -g @mindfoldhq/trellis@latest

在仓库里初始化

-u 是开发者身份。可加平台 flag，如 --cursor --codex。

trellis init -u your-name

自然语言 + continue

描述需求 → AI brainstorm 写 PRD → 一路 continue 推进实现与检查。

/trellis:continue

做完再收尾

先 commit 工作改动，再 finish-work：归档任务并写 journal。

/trellis:finish-work

按场景查

先找当前要做的事，再复制对应命令。

第一次给项目装 Trellis

创建 .trellis/、默认 Spec 模板，以及 00-bootstrap-guidelines 任务。别跳过 bootstrap。

initbootstrap
trellis init -u your-name --claude

给已有项目加平台

在已有 .trellis/ 上叠加平台配置目录，不新建任务。

platformcursor
trellis init --cursor --opencode --codex

新人 clone 已有 Trellis 项目

有 .trellis/ 但没有本机 .developer 时，会生成 00-join-<slug> 入职任务。

joineronboard
trellis init -u their-name

升级 CLI 和项目模板

两步：先升全局 CLI，再在项目里 sync。出现 MIGRATION REQUIRED 时加 --migrate。

upgradeupdate
trellis upgrade && trellis update

AI 卡住或跳步了

按当前 task 状态和 workflow breadcrumb 推进下一步。不必自己记阶段命令。

continue
/trellis:continue

会话结束 / 上下文快满

要求工作改动已 commit。会归档完成任务并追加 journal。

finish-workjournal
/trellis:finish-work

用 Spec 模板起步

官方 marketplace 或自定义 registry。已有 Spec 时用 --overwrite / --append。

templatespec
trellis init -u your-name --template electron-fullstack

临时对比有无 Trellis

消融会备份后移除项目级表面；对比完 restore。不同于永久 uninstall。

ablaterestore
trellis ablate --dry-run

手动创建 / 查看任务

通常 AI 会调 task.py。需要手操时直接跑脚本。

task
./.trellis/scripts/task.py list --mine

只关 hooks，不卸 Trellis

临时禁用会话注入 hooks。消融 / 卸载是更重的操作。

hooks
TRELLIS_HOOKS=0

Codex 要先开 hooks

否则 / 菜单看不到 Trellis 命令。开完再跑一次 /hooks 批准。

codexhooks
features.hooks = true # ~/.codex/config.toml

看当前上下文快照

身份、git 状态、活跃任务、Spec 索引。收尾模式用 --mode record。

context
./.trellis/scripts/get_context.py

常用流程

把几条命令串起来，覆盖真实使用。

从零到第一次任务

装 CLI → init → 跑完 bootstrap 填 Spec → 用自然语言开第一个真实任务。

npm i -g @mindfoldhq/trellis@latest→trellis init -u you→bootstrap Spec→描述需求

日常一个完整任务

skill-first：你几乎只需要自然语言和两个 slash。

描述需求→/trellis:continue→…→/trellis:finish-work

跟上新版本

CLI 与项目模板版本分开。有 breaking 变更再 --migrate。

trellis upgrade→trellis update→必要时 --migrate

内部四阶段循环

多数由 auto-trigger skill / sub-agent 自动跑，用户侧靠 continue 推进。

brainstorm→implement→check→update-spec

做有无 Trellis 的对照实验

消融后请新开 agent 会话；结束后精确恢复。

trellis ablate→新开会话对比→trellis restore

同一仓库服务多个 Agent

.trellis/ 核心共享；各平台只差 commands / skills / hooks 目录。

trellis init --claude→trellis init --cursor --codex

这些路径各管什么

搞混 Spec / Task / Workspace，是“AI 不记得项目约定”的最常见原因。

路径 装什么 谁写
.trellis/spec/ 项目编码规范与可执行契约。会话里按任务注入相关层。 你 + trellis-update-spec。建议版本化进 git。
.trellis/tasks/ 任务单元：task.json、prd.md、可选 design/implement、jsonl、research。 AI 经 task.py 创建；完成后进 archive/。
.trellis/workspace/{name}/ 个人会话 journal。跨会话记忆靠这里。 finish-work 调用 add_session.py 追加。
.trellis/workflow.md 开发工作流契约。每次会话起点。 Trellis 模板；可用 trellis update 同步。
.trellis/config.yaml packages、update.skip、任务生命周期 hooks。 你。hooks 默认注释掉。
.trellis/.developer 本机开发者身份。gitignored，不进仓库。 trellis init -u 写入。新人 clone 后没有它。
.trellis/.runtime/sessions/ 每个 AI 会话/窗口的当前任务指针。 task.py start/finish；gitignored。
.claude/ · .cursor/ · … 平台适配：commands、skills、agents、hooks。 trellis init / update 生成。

CLI 索引

在系统终端运行。权威来源是官方文档与 trellis --help。

命令 什么时候用 备注
trellis init -u name 首次装到仓库、加平台、或新人加入。 按 .trellis/ × .developer 三路分发。
trellis upgrade 升级全局 CLI package。 --tag latest / --dry-run。
trellis update 把项目模板同步到本地 CLI 版本。 breaking 时加 --migrate。
trellis ablate 临时移除项目级 Trellis 表面做对照。 先在项目外做恢复事务。
trellis restore 从 ablate 事务精确恢复。 受管路径被改过会拒绝写入。
trellis uninstall 永久移除项目级 Trellis。 不同于 ablate / TRELLIS_HOOKS=0。
trellis --version 确认本地 CLI 版本。 和项目 .trellis/.version 可能不同。

Slash / Skill / Sub-agent

0.5+ 是 skill-first：用户侧主要记 continue 与 finish-work。平台调用写法略有差异。

名称 类型 什么时候用
/trellis:start Command 无自动注入的平台手动加载上下文。多数 hook 平台不装用户可见 start。
/trellis:continue Command 当前任务内推进下一步。Cursor 等写作 /trellis-continue。
/trellis:finish-work Command 工作 commit 之后：归档 + journal。工作区有未提交代码改动会拒绝。
trellis-brainstorm Skill 同意建任务后：逐题澄清需求，写 prd.md，需要时派 research。
trellis-before-dev Skill 动手改代码前自动读相关 Spec。
trellis-check Skill / Sub-agent 对照 Spec 审 diff，跑 lint / typecheck / test，自修复。
trellis-update-spec Skill 把决策 / 约定 / gotcha 写回 .trellis/spec/。
trellis-break-loop Skill 修完难 bug 后做 5 维根因与预防分析。
trellis-implement Sub-agent 按 PRD + jsonl 上下文写代码，不 git commit。
trellis-research Sub-agent 只读搜索代码 / 文档；发现写入任务 research/。

task.py 速查

脚本在 .trellis/scripts/task.py。日常多由 AI 调用；下面是手操索引。

子命令 什么时候用 示例
create 新建任务目录 + 默认 prd.md。 task.py create "新增登录" --slug user-login -p P1
add-context 往 implement/check jsonl 加 Spec 或 research 路径。 task.py add-context "$DIR" implement ".trellis/spec/…" "原因"
validate / list-context 校验 jsonl 引用存在；查看全部条目。 task.py validate "$DIR"
start / finish 设置或清除本 AI 会话的当前任务。 task.py start "$DIR"
set-branch / set-scope 写分支名、PR 目标、commit scope。 task.py set-scope "$DIR" "auth"
add-subtask / remove-subtask 链接或解除父子任务。子任务是独立目录。 task.py add-subtask parent-dir child-dir
list / archive / list-archive 列活跃任务、归档、按月看归档。 task.py list --mine --status review

平台调用差异（摘）

同一语义，不同平台写法不同。完整表见官方 Appendix B。

平台 Continue Finish
Claude Code / OpenCode / Gemini / CodeBuddy / Droid /trellis:continue /trellis:finish-work
Cursor / Pi Agent / Qoder /trellis-continue /trellis-finish-work
Kiro @trellis:continue @trellis:finish-work
Kilo /continue.md /finish-work.md
GitHub Copilot Run Prompt → trellis-continue Run Prompt → trellis-finish-work
使用习惯

先跑通 bootstrap 把 Spec 从空模板填成真实约定，再开业务任务。日常几乎只要自然语言 + continue；阶段 slash（如 before-backend-dev）在 0.5 已移除。升级永远是 upgrade（CLI）再 update（项目）。对照实验用 ablate/restore，不要和 uninstall 搞混。
